# 运维笔记（脚本机制与每日流程）

## 每日抢购流程

```bat
:: 1. 自检（登录态 / 人脸核身 / 购买资格 / 当日场次 business id）
python morning_check.py

:: 2. 全绿后拉起当日 10:00 与 15:00 两场后台监听
python launch_today.py
```

或直接双击 `早上抢购.bat`（自检 + 启动一步到位）。

单场运行（指定任意时间）：

```bat
python snap_up_server.py "2026-01-01 10:00:00"
```

## 关键机制（实测确认）

| 机制 | 说明 |
| --- | --- |
| **x-csrf-token** | 由 `skey` cookie 经 g_tk 算法（djb2 哈希 & 0x7FFFFFFF）计算，无需浏览器；`qcmainCSRFToken` 明文不可用 |
| **business id** | 即场次 id，每天变化；`None` 时启动自动从 `query-seckill-by-date` 拉取（按目标开售时间精确匹配） |
| **钟差校准** | 服务器 `Date` 头只有秒级精度，校准取 5 次采样中位数、`+500ms` 对中、计入半 RTT |
| **开抢节奏** | 提前 1500ms 起打；每轮 3 地域并发；轮间 350~600ms 抖动；408 退避 1.5s；单请求超时 3s；重试窗口 30s |
| **场次窗口** | 10:00~12:00 / 15:00~18:00；库存通常在开点后 1~2 秒内被抢完 |

## 返回码速查（详见 docs/错误码手册）

| 码 | 含义 | 动作 |
| --- | --- | --- |
| 0 | 成功 | 去控制台付款（1 小时内） |
| 1100136 | 售罄 / 未开闸 | 继续重试 |
| 1100205 | 系统繁忙 | 继续重试（核心重试目标） |
| 408 | 限流 | 退避 1.5s |
| 1100110 | 正在执行其他操作 | 说明有请求正在下单中，继续重试 |
| 1101411 | 有未支付订单 | 停止重试，去付掉或取消旧订单 |
| 1100202 | 需人脸核身 | 先完成人脸核身，重试无意义 |
| 1100204/1100208/1100209 | 资格/限购不符 | 重试无意义 |

> 注意：**下单请求 ReadTimeout ≠ 失败**。服务端可能已落单，只是回包丢失。看到 `1101411`（有未支付订单）说明订单已生成，立即去付款页面处理。

## 常见操作

- 登录态一般数天有效；`morning_check.py` 报 `NOT-LOGINED` 时运行 `python get_cookies.py` 重新扫码（该脚本会在登录后顺带检查人脸核身状态，未通过会引导完成）。
- 抢到后脚本会自动打开（或打印）订单付款链接；订单通常 1 小时内未支付会被释放。
- 保持电脑不休眠、网络畅通；监听进程在到点前 60 秒才联网校准，对时后到点开火。
